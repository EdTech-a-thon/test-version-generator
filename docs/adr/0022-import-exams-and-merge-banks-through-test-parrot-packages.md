# Import Exams and merge into existing banks through Test Parrot Packages

Teachers converting their tests expect to come away with the test, not just its questions: `/get-started` created an Exam after import but left it empty. They also convert several tests that belong in one bank. ADR-0018 ruled both out, since import “never merges, replaces, creates an Exam, or changes a Working Copy”. This ADR supersedes that sentence only. All-or-nothing validation, fresh local identities, content-addressed Media Assets, discarding unknown optional fields, and the PDF attachment identity all stand.

An Exam travels as an **Exam Record**, a new format (`test-parrot/exam`) versioned separately from the Question Bank Record, because the two will change at different rates. Neither is imported alone when an Exam is involved. A **Test Parrot Package** (`test-parrot/package`, `.parrot.json`, itself separately versioned) carries one or more Question Bank Records, each under a package-local bank id, and any number of Exam Records. One Question Bank Record embedding an Exam layout was rejected because it would couple the two versions, and a limit of one Exam per file was rejected because the importer can offer a choice just as easily. A bare Question Bank Record is still importable and counts as a package with one bank and no Exams; the Question Bank Record format does not change.

An Exam Record holds the Exam's name and an ordered list of positions. Each position references `{bank, question}` by package-local ids, with optional answer columns (Multiple Choice), answer order (Multiple Choice choices or a Matching Word Bank), and Work Space (Short Answer). A package is rejected whole if an Exam references a missing bank or Question, or uses one Question twice. A bank may hold Questions no Exam uses. An Exam may draw on several banks in its package but never on a bank that is already in the app. Order across Sections is ignored without comment: positions are regrouped into Test Parrot's Section order, keeping only the order within each Section, because a source test that puts Short Answer first cannot be represented and rejecting it would be harsh. Exam Records carry no point values, since Exams have none.

The import review lists every bank and Exam in the package with a preview of each and the dependencies between them (“this bank feeds these Exams”, “this Exam uses these banks”). The teacher allows or denies each one. Denying a bank automatically denies every Exam that uses it, with the reason shown, and allowing such an Exam again re-allows its banks, so an allowed Exam is always valid. Individual Questions can be previewed but not excluded, because excluding one would leave a hole in an Exam. Each allowed bank goes either to a new Question Bank (its name editable, defaulting to the record's) or into an existing bank chosen by the teacher. Merging always appends fresh Questions, never deduplicates, and discards the incoming bank's name, description, author, and license. An Exam imported alongside a merged bank references the newly appended Questions. The dialog title follows the package: “Import Question Bank”, “Import Question Bank and Exam”, or “Import 3 Question Banks and 2 Exams”. Dropping a file on a Question Bank's page or on the editor's Question Bank panel starts the same flow, with every bank defaulting to that bank. When import finishes, the teacher lands where they did before if no Exams were imported. With exactly one Exam, it opens in the editor with its banks as tabs; with more than one, the teacher goes to the Exams collection.

An exported Exam PDF whose Content Selection includes the answer key embeds a Test Parrot Package under the same `pdf-canonical-extraction` attachment identity Question Bank Files use. The package holds one Exam Record for exactly what that export printed, plus, for each owning bank, only the Questions that Exam uses. Student-only PDFs embed nothing, because Question Bank Records contain the answers. DOCX exports embed nothing, because a teacher's Word edits would leave a stale package that disagrees with the page. The importer reads that attachment and accepts either a bare Question Bank Record or a package. The package is recorded in the Export Record, so a historical re-export reproduces it, but it is excluded from the Export Fingerprint and the print/DOCX parity comparison, which stay about pages. Question Bank Files keep embedding a bare Question Bank Record.

The AI extraction instructions produce a package with one bank and one Exam when the source is a test, recording answer columns only where the layout makes them clear and never guessing Work Space. When the source is only a list of questions, they produce a bare Question Bank Record, as before. Merging two banks that are already in the app, which moves Questions between banks, remains future scope as ADR-0011 left it.
