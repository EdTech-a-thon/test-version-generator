# Read other tools' question files without AI

Some teachers will not send their tests through an AI. That is an ethical choice, not a workflow preference, and the AI conversion of ADR-0027 cannot serve them. Most of them already have their questions in a file some other tool reads: the plain text of the Blackboard Test Generator (Oklahoma Christian University's, and the Algonquin and College of Southern Idaho tools it came from), Blackboard's tab-delimited upload and its pool exports, QTI from Canvas and Brightspace, Moodle XML, GIFT and Aiken, Respondus, text2qti, Brightspace CSV, Kahoot and generic spreadsheets, and Quizlet and Anki cards. Each of these formats is documented or reverse-engineered well enough to parse exactly, so Test Parrot reads all of them with rules alone. It never calls a model and never sends their content anywhere.

Every format has its own parser, a pure function of the file's bytes. Each parser yields questions in the format's own terms, and one converter turns them into a Question Bank Record, so a dropped Question File goes through the same inspection, preview and confirmation as a Test Parrot file. A kind Test Parrot has no Question Type for is converted the same way whatever file it came from, and the teacher is told. Fill in the blank, numeric, essay and ordering questions become Short Answer, with the accepted answers, the value, the model answer or the order kept as the Suggested Answer. Multiple Answer ("select all that apply") becomes Multiple Choice. With one correct choice nothing changes. With several, it arrives with none marked and the teacher is told which were correct, because a Test Parrot question has one correct answer. We rejected keeping only the first correct choice, which would silently change the question.

A file is recognised by scoring it against every format and then reading it with the three that score best. The winner is the reading that combines the best score with the largest share of questions brought in. A format's score comes from its own markers: a standalone `MC` line appears only in the Blackboard Test Generator's format, `ANSWER: B` only in Aiken, and `Type:` or `Title:` only in Respondus. Where formats share a layout, such as `1.` / `a)` / `*b)`, a fixed order breaks the tie, and the Blackboard Test Generator comes first because its customers asked for this. The preview names the format a file was read as and offers every other one, so a wrong guess costs a click, not a wrong import. Questions that cannot be read are left out, each named with its line and what to fix, and the rest still come in. Blackboard itself behaves the same way.

A Word document is tried as a Question File first and converted by an AI only when it reads as none, with a way to convert it anyway. Questions a teacher has only as text can be pasted, because pasting is how the Blackboard Test Generator itself is used. A PDF is not read this way. Its text has no reliable structure, and the Question Bank Record specification's rule against reconstructing questions from PDF text still stands.

The XML reader expands no DTD and no external entity, and HTML keeps only what the record can say. A ZIP is opened within fixed limits on entries, sizes and compression ratio, and an entry whose name leaves the archive is refused. Pictures come from the file itself when it carries them: Blackboard's `csfiles`, QTI's package files, and Moodle's base64. Otherwise they are added by hand after importing.
