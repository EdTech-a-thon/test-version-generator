# Resolve AI-imported pictures from a tagged Source Document

An assistant converting a teacher's test into a Test Parrot Package cannot reliably carry its pictures. A Media Asset needs exact base64 bytes and a SHA-256 digest, which no assistant can type, and only some can produce with code execution; Gemini, the assistant most teachers use, cannot. So Test Parrot supplies the pictures itself, from the Source Document the teacher converted. The Question Bank Record specification says importers must never reconstruct Questions from PDF text, images, or layout. This ADR narrows that rule rather than overturning it: Question Content still comes only from the record, and the Source Document supplies nothing but the bytes for Pending Images.

The import starts from the Source Document. The teacher drops their PDF into Test Parrot, which rips every embedded image and prints an Image Tag, “IMG 1”, “IMG 2”, and so on in reading order, inside the top-left corner of each picture-sized image on a labeled copy. Tags sit inside the picture because a covered corner costs nothing (the bytes come from the original) while a tag beside it can hide question text. Images too small to be pictures, such as equations stored as images, get no tag. The teacher copies instructions that list the document's tags, gives the assistant the labeled copy, and drags the returned package back into the import that is still waiting with the Source Document selected. The assistant writes each picture as a Pending Image naming its tag, `{"pending": {"image": 3}}`, splitting side-by-side pictures and repeating a shared picture in every Question that uses it. A picture with no tag, such as a vector diagram, a scanned page, or any picture from a source that was not uploaded first, is written as `{"pending": {"page": 4}}` and resolved by cropping or uploading. This needs Question Bank Record `0.4.0`.

We measured the alternatives on two real tests: a function-theory test with up to five graphs on a page and graphs as answer choices, and a history packet the matching code was never tuned on. Boxes drawn by Gemini around each picture overlapped none of 14 pictures; they were templated guesses. Gemini's page numbers were right for all 10 pictures in the packet but wrong for 18 of 22 in the function-theory test, where it wrote page 1 throughout, and a page cannot tell four graphs apart anyway. Matching ripped images to the record through the PDF's own text layer, by question text and answer labels, placed all 19 picture slots of the test it was tuned on but only 4 of 10 in the packet. With tags, Gemini placed all 19 slots of the test and all 10 of the packet, in order, and never copied a tag into content. We also rejected a dummy base64 placeholder, because it fails the Media Asset integrity checks and cannot be told apart from a corrupt record, and we dropped the path where a code-capable assistant embeds real bytes, so every assistant follows one set of instructions. The format still accepts embedded Media Assets, which Question Bank Files and Test Parrot's own exports rely on.

The Source Document is kept in the browser only while its import is in progress: it is deleted when the import finishes, when the teacher discards it, or after seven days, and it never enters an Account Backup or Account Sync. One import waits at a time. Because the waiting import already holds the Source Document, the returned package needs no identifier; Test Parrot only checks that its tags exist and that its question text appears in the document, and warns that the file seems to come from a different test when either check fails. Resolve Images ends the import: it shows every Pending Image, with tag matches already accepted, and lets the teacher swap in another image from the document, crop any page, or upload a file. Reopening it later for Pending Images that remain asks for the Source Document again. A Pending Image may stay unresolved in its Question Bank and travels as it is in a Question Bank export, but an Exam export refuses while any of its Questions still has one. A reading passage that the source stores as an image should be transcribed; an assistant that keeps it as a picture instead is accepted, since the picture prints faithfully.
